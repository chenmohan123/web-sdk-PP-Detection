本清单沿用门户 `standards/v1/templates/demo-checklist.md` 的状态、缓存、耗时和布局语义。
用户已在小米 15 完成基础功能实测；实际 HyperOS/Android 版本和完整验收项目仍待补充。桌面 390px 视口仅作为布局证据。

## 打开当前开发版本

当前 GitHub Pages 公开版本尚未随本轮改动部署。先在电脑仓库构建 SDK 并运行 Demo：

```powershell
pnpm --filter web-sdk-pp-detection build
pnpm --filter @ppdetection/demo dev --host 127.0.0.1
```

使用 USB 时，在手机开发者选项中开启 USB 调试，连接电脑并在手机确认该电脑的调试授权。
电脑使用 Android 官方 Platform Tools 执行：

```powershell
adb devices
adb reverse tcp:4174 tcp:4174
```

`adb devices` 中设备应为 `device`，`unauthorized` 表示手机尚未确认。
在手机 Chrome 打开 `http://localhost:4174/`，不要添加 `fixture` 参数。
localhost 可使用 Web Crypto 等安全上下文功能；普通局域网 HTTP 地址不适合验证这些能力。
测试完成可运行 `adb reverse --remove tcp:4174` 解除映射，再按个人习惯关闭 USB 调试。

不使用 USB 时，可以使用受信任的 HTTPS 预览。此次测试使用电脑 `10.11.3.9:8443` 的临时 HTTPS 入口和本地证书；该入口依赖当前电脑服务及局域网，不是公开部署地址。

## 按顺序操作

1. 记录手机型号、HyperOS/Android 版本、Chrome 版本和日期时间。记录网络、是否充电、省电模式及手机是否明显发热；同一轮保持条件一致。
2. 确认默认 PicoDet、中文界面；选择示例图片，点击“清理全部缓存”，选择 CPU，然后开始检测。记录首次下载、校验、Session 和总耗时；展开运行时信息，确认实际后端为 `wasm`。
3. 原图连续再检测 3 次，分别记录推理与总耗时、模型获取来源；图片模式每次点击会重建 Session，不能把含 Session 的加载时间当成复用 Session 的热推理时间。
4. 切换 PP-YOLOE+ S 640，确认稳定状态可见、旧结果和耗时撤下、当前模型版本为 `0.1.0`。其 FP32 文件为 31,954,220 字节，SHA-256 为 `d3ae6a9f75311e7a05b535c4c0d4a1cdaad6342f87a0339cef5b4e52b106749c`。
5. 显式选择 ModelScope，对相同图片重复首次检测和 3 次检测，导出 JSON 结果；清理当前模型缓存后，切换 Hugging Face 再执行一次首次检测。记录每次实际来源、后端、运行模式、ORT 版本、推理耗时及可见错误；来源失败应显示错误，不得静默换源。体积与哈希按清单和完整性校验结果确认。
6. 点击“清理当前模型缓存”，确认当前容量归零且旧检测框撤下；切回 PicoDet，确认其缓存仍存在。点击“清理全部缓存”，确认本 SDK 总容量归零。
7. 对 PP-YOLOE 分别尝试自动后端和 GPU。自动模式如发生回退，记录实际后端及原因；显式 GPU 不支持时记录错误，不记为通过。浏览器支持 WebGPU 的判断以本机运行结果为准。
8. 在下载/加载过程中取消或切换模型，确认旧任务结束后不会覆盖当前模型和结果。切回后能重新开始检测。
9. 检查竖屏没有横向滚动；语言切换、图片缩放、类别筛选及 JSON 导出可用。若验证摄像头，确认关闭后系统相机使用指示消失，并单独记录权限与连续帧结果。
