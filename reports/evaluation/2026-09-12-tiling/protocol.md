# 小目标切片检测预先固定评估规则

本轮为一次性可行性实验，使用已发布 SDK 0.3.2 与现有六个稳定模型，不增加产品 API 或修改线上 Demo。

- 固定此前选定的 COCO val2017 64 图、716 条标注（700 条非 crowd，其中面积小于 32² 的 399 条）。图像尺寸 288–640 × 307–640，沿用图片 SHA-256 与类别原始 ID 映射，不根据结果挑选评测图片。
- 比较整图、仅切片、整图＋切片。每轴两片，片长为 ceil(原长 / 1.8)，分别贴近两端，目标重叠比例 20%；共四片，每片保持原像素，直接裁切 RGBA，无额外缩放。后续预处理与推理由正式 SDK 执行。
- 模型内置 NMS 与清单的 IoU 0.5 保留；检测阈值设为 0.001 供 COCO AP 使用。仅切片和组合输出映射到原图后，使用同类别 IoU > 0.5 的贪心 NMS，按置信度排序，相同分数保留原顺序。整图输出保持 SDK 结果。
- 两模型的 FP32、FP16、W8A32 均在物理 WebGPU 和单线程 WASM 下各运行完整 64 图。每组合先执行一张图的整图和四片预热；实际后端必须匹配请求，无回退。组合串行执行；每图交替整图/切片先后次序。
- 图像统一解码一次。记录解码、整图检测、逐片检测、裁切、合并和完整处理耗时；模型加载单独记录。报告中位数与 P90，不将本机文件读取算作公网下载，也不将单轮结果解释为稳定加速或手机性能。
- 质量使用官方 pycocotools：AP、AP50、APSmall/Medium/Large 与召回。另在 score >= 0.5、IoU >= 0.5 下按 COCOeval 的一对一匹配与 crowd 忽略规则统计 TP、FP、FN，以及新增/丢失的小目标标注 ID。
- 判断首先看小目标召回与 AP 是否同步改善，再比较整体 AP、误检和每图开销。保存全部原始框和失败案例；本样本属于探索性证据，参数与模式比较不等同于独立测试集验证。

可复现脚本放在 reproduction，标为一次性实验；本轮不重新转换、分发或标记模型稳定性。若效果支持下一阶段，再确定大图样本、切片上限、边缘截断处理和可取消流程的产品设计。
