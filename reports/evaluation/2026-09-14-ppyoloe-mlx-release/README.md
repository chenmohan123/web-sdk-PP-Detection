# PP-YOLOE+ M/L/X 精度变体发布验证

日期：2026-09-14。M/L/X 六个 FP16、W8A32 变体通过固定 64 图的桌面 WASM/WebGPU 三轮识别门槛；每个变体只与同规格、同轮、同后端的 FP32 对照。模型与 Demo 独立发布，M/L/X 新清单为 0.1.1，SDK/npm 保持 0.4.0。

全部 54 组完整浏览器运行通过。新增变体 AP 最大下降 0.348 个百分点，常规识别保留率最低 97.43%。FP16 文件约缩小 50%，W8A32 约缩小 75%；文件缩小独立计为收益。

## 协议与范围

- 本轮使用用户在验证前确认的[固定协议](protocol.json)：AP 下降≤0.5 个百分点，score≥0.5、同类 IoU≥0.5 的一对一匹配保留≥95% FP32 检测。IoU≥0.99 仅作坐标偏差诊断，不参与本轮发布判断。
- 第一轮复用[旧批次](../2026-09-14-ppyoloe-mlx-precision/README.md)已归档的18组完整运行，再独立补第二、第三轮。旧批次的严格坐标门槛和 labs 结论保留原样；本轮没有改写旧结果。
- 固定 COCO val2017 场景子集64图、716标注，浏览器使用原JPEG与SDK bicubic；WASM单线程、main模式、关闭缓存和SDK后端回退。图片、标注、清单、权重、SDK和环境身份均逐项校验。
- 旧9组Python结果使用OpenCV预处理，其中6项候选作为单轮诊断单独记录，不加入浏览器三轮发布门槛，不与浏览器跨预处理逐框比较。
- 这是固定子集回归，不是完整COCO成绩；没有新增手机、其他浏览器或峰值内存验证。

## 复算与证据

`artifact-index.json` 固定第二、三轮的72份压缩结果与绑定。第一轮索引必须逐字节匹配 Git 提交 `e4814a44d42be5e213ef416cd0dfb2d7932c2340` 中的同路径文件，继而校验其全部gzip；旧摘要另有固定SHA。每个组合三轮的结果SHA与capturedAt必须互异，时间严格递增。全部GPU记录须具有相同物理适配器身份；第一轮AP和两种匹配计数还会与固定旧摘要交叉核对。

在包含上述固定提交的Git检出中，使用已有COCO评测依赖：

```powershell
$env:PYTHONIOENCODING = "utf-8"
& .tmp/phase2/venv/Scripts/python.exe reports/evaluation/2026-09-14-ppyoloe-mlx-release/summarize.py
& .tmp/phase2/venv/Scripts/python.exe -B -m unittest discover -s reports/evaluation/2026-09-14-ppyoloe-mlx-release -p test_evidence.py
```

复算只读取Git提交、版本清单、标注与压缩结果，无需下载ONNX或图片、无需构建SDK。第一次从工作目录归档使用 `summarize.py --archive`；重新执行实际推理使用 `node reports/evaluation/2026-09-14-ppyoloe-mlx-release/browser.mjs`，该入口需按旧jobs准备同SHA权重、图片和SDK bundle。

错误证据检查在系统临时副本中执行，覆盖gzip损坏、重建索引但偏离固定根、重新绑定的重复轮次、错误协议摘要、GPU身份变化、重复jobs、score参数与Python优化模式；不修改原始结果。
